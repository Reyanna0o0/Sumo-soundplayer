## 流播与首播等待

三种格式均在全文读取完成前开始推进媒体时钟。本机 HTTP 夹具以 8 倍媒体码率限速，首个 GET 到首次进度事件约 MP3 1.89 秒、M4A 17.74 秒、WAV 1.23 秒。首次进度前已请求范围的保守上界分别约占文件 18.20%、83.71%、10.31%。这不是精确已发送字节或持久缓存测量。

对 `preferredForwardBufferDuration=5` 的完整三格式对照没有明显缩短 M4A 首播，生产配置保留系统默认 0 和自动等待策略。本批没有宣称解决 M4A 限速首播等待，后续需要区分容器加载与 AVPlayer 缓冲等待，结合真实 NAS/外网继续优化。

定位验证观察的是媒体时钟到达目标后继续前进，字幕采用 5 秒分段夹具；不是声学或采样级准确度认证。网络 WAV 仅覆盖本次 PCM 变体，不能外推所有 WAV 编码。

## 测试环境问题与修正

- 全局命令行覆盖 App bundle ID 会错误传给动态 framework，模拟器首次安装因此被拒；测试改为 App 身份独立设置，正式设备包保留独立的 `amsmb2.AMSMB2` framework 标识，打包脚本新增重复标识检查。
- 未签名模拟器包缺少钥匙串身份，持久化返回 OSStatus -34018；手工给 macOS ad-hoc 签名加入受限 iOS 权限也被 AMFI 拒绝。最终使用 Xcode 标准的模拟器 entitlement 链接/打包流程，认证通路通过。没有绕过产品钥匙串，也没有改变正式 IPA 的签名要求。
- 忙状态的 `@Published` willSet 通知曾暴露指令竞争，现使用同步屏障，并在解除屏障后再发空闲通知，实际竞态复测已通过。

## 尚需真机验收

家庭 NAS、不同服务器实现、外网/校园网、真机锁屏/后台、真实 Wi-Fi 断连、声学输出、超过本次合成规模的大库、各第三方文件提供方及低电量/突然断电仍需验证。注入目录交换中断检验的是进程恢复，不等于断电耐久保证。导出与准备恢复期间保持 App 在前台。

外部/NAS 音频不复制，恢复后重新授权或填写凭据；本批不含 NAS 按作品离线下载管理。具体操作和集中真机清单见 [NAS 与整库备份](NAS_AND_BACKUP.md)。
