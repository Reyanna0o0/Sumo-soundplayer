# NAS 与整库备份：开发候选版

本页对应 `codex/nas-and-library-backup` 的开发候选，不代表 GitHub 上既有 0.1.4 安装包已经具备这些入口。真机和家庭 NAS 的验收清单见下文。

## 添加网络作品

1. 打开设置 → NAS 与网络来源 → 添加网络来源。
2. 首次出现本地网络权限提示时允许访问。SMB 填写 `smb://服务器/共享名/目录`；WebDAV 填写已开放 WebDAV 服务的目录地址；HTTP/HTTPS 填写一个 MP3、M4A 或 WAV 的直接文件地址。
3. 填写该共享允许使用的账户。只有服务器本身支持匿名访问时才留空用户名。密码保存在本机钥匙串，不进入备份。使用 HTTP 需要为该来源单独启用许可；HTTPS 仍验证服务器证书。
4. 浏览指定目录，手动选择音轨，填写作品名，选择个人音声或社团作品。个人音声可选作者，可手动选择本地封面。只导入所选文件的资料，不扫描或搬入整个服务器。
5. 回到既有媒体库播放。作品和音轨编号独立于地址，播放进度、列表和字幕继续使用原来的控制层。

离线仍可查看已导入的作品资料、列表及本地封面。音频按需读取，当前网络曲目没有完整文件时不提供波形摘选/导出。已导入的本地字幕可按播放时钟同步；本批不自动下载远程旁挂封面或字幕，也不新增 NAS 离线下载任务管理。

普通 HTTP 地址不等于可浏览的目录列表；目录浏览使用 SMB 或 WebDAV。当前验证范围为 Basic/匿名 HTTP/WebDAV 和 SMB 用户名密码；未提供 Digest、NTLM HTTP 认证、签名查询参数 URL 或证书绕过。

## 换地址与重新连接

设置中编辑同一条来源，核对并重新绑定，保留作品与音轨编号。重绑定只核对已经导入的音轨，不扫描新作品。当前音轨可在播放器中点重新连接，后续加载使用新位置。目录内相对位置应保持一致；可用的大小/修订信息只提供部分核对，大小相同不证明内容完全一致。

停用来源会保留作品资料并清除凭据。恢复备份后，外部文件夹需重新授权或关联，NAS 需重新填写凭据；恢复资料并不代表旧设备的访问权限也已搬迁。

## 备份与恢复

换机顺序：旧机保留原 App → 覆盖更新到带备份入口的版本 → 设置中导出并把备份另存到电脑或可从新机访问的位置 → 新机签名安装 → 导入备份、校验并恢复 → 核对媒体与资料。既有 0.1.4 没有这个入口，不能用旧版本直接生成整库备份。覆盖更新应沿用旧机原有的签名身份和 App 标识，不要先卸载；如果安装工具显示为第二个 App，先停止迁移并核对标识。只有新机核对完成后再处理旧机。

设置 → 整库备份与恢复。先停止编辑与导入，再导出备份，并将备份保存到设备以外的位置。导出暂停播放并保存当前进度/统计；数据库使用包含 WAL 最新内容的一致快照。

备份包含 App 自有媒体、作品资料、封面、字幕及其历史、列表、摘选、收听记录和支持的偏好设置。外部文件夹及 NAS 音频不复制，来源记录保留；密码、系统临时缓存和升级前数据库副本不作为整库媒体重复打包。

在新机独立签名安装兼容版本，选择备份后先校验，再确认恢复。恢复替换当前资料库而非合并，校验通过后按页面提示关闭并重新打开 App。切换失败会尝试回滚；旧资料的回滚副本保留在本机，不能代替另存的备份。备份包含私人资料和媒体，按自己的资料保管。

只复制“文件”App 中的厮磨目录或单个 `hibiki.db` 不等于整库备份。系统 iPhone 数据传输也不会替 App 完成新设备上的侧载签名安装。

## 集中真机验收

使用测试作品和可留存的测试备份，先保留旧机 App 及原始资料。

- 三种皮肤：米白、浅黑、紫色下检查设置、来源表单、目录、确认提示、播放器状态和备份页；删除/停用/覆盖确认应居中。
- 同局域网分别测试电脑 SMB 共享及 NAS WebDAV；HTTP 测一个直接文件 URL。检查正确密码、错误密码、无权限、文件不存在和中文/空格文件名。
- MP3、M4A、WAV 各测试首播、拖到前/后位置、倍速、字幕同步、切下一首、暂停后重新连接，确认不会自行恢复播放。
- 真机锁屏/后台播放；断 Wi-Fi 后跳到未缓存位置，确认留在当前音轨且有提示；重连后从原位置继续。缓存仍可播放一小段属于预期，不能把这段当作断网恢复成功。
- NAS 离线时仍能打开作品与列表；改地址重新绑定后编号、收藏、字幕、统计、播放位置保持一致。
- 用合成资料导出→另一个空安装恢复，检查个人/社团作品、封面、当前与历史字幕、摘选、列表、顺序、收听统计、设置及 App 内音频。外部/NAS 媒体应提示重新连接。
- 损坏/不兼容/空间不足的备份应拒绝恢复且原库仍在。大库备份中断后重新导出；只有完成并校验的备份才可用于迁移。

## 源码与重建

协议核心位于 `Prototypes/ResourceAccess`，正式桥接为 `Prototypes/ResourceAccessAMSMB2`。后者使用 `Prototypes/Vendor/AMSMB2` 中固定来源、保留本地修补记录的完整动态库源码；本 App 的正式播放入口仍为 `PlayerController`。AMSMB2 与 libsmb2 的许可和修补记录随源码保留，安装包中携带动态 framework 及许可副本。可修改这些源码，按 `BUILD.md` 重建，并使用自己的签名身份重新安装。

本机自动化报告应区分核心测试、模拟器实际播放、真机及家庭 NAS。通过前两者不能代替后两项验收。
